Start here

Connect in three steps

  1. Choose an address your AI can reach. A local AI can use loopback. Another computer needs your encrypted tailnet address, or an HTTPS endpoint you have configured.
  2. Create an individual AI key. In Settings, choose read access or read + append. Set an expiry and share the key privately with that assistant.
  3. Give it the guide and test the connection. Download the Markdown handoff below. Check identity and health before the first search or import.

For assistants and developers

Direct REST access

Send the assigned key in the Authorization header. Discovery itself contains no private knowledge.

Read and append workflow
  1. GET /api/auth/me and /api/capabilities for your permissions and limits.
  2. GET /api/search?q=…&k=6, then GET /api/chunk/{id} for passages and provenance.
  3. To append, POST /api/ingest/text or /api/ingest/url with an Idempotency-Key.
  4. Poll the returned job ID every 10–15 seconds. Wait for ok or failed; acceptance alone does not mean the import completed.


MCP for compatible assistants
The adapter runs on the AI’s machine and talks to this server over the same protected REST API. It exposes focused knowledge tools.
Clone the Bifröst repository on the AI’s machine and replace the example directory. Put the real key in that machine’s secret settings; the template deliberately contains a placeholder. Add BIFROST_ALLOW_APPEND=1 only for an AI authorized to add knowledge.

Access with clear boundaries
Individual keys expire and can be revoked. Requests and imports have bounded quotas. An append key cannot edit existing sources, delete knowledge, or administer your brain.
On 429, respect Retry-After. On an uncertain submission, reuse the same key and unchanged payload. Stop on 401 or 403 and ask the owner for access.
